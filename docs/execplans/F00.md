## Validação e critérios de término

A prova principal executa código upstream, não um substituto local do Hermes. Provider fixture comprova transporte/orquestração e é identificado como fixture; não comprova qualidade, preço ou compatibilidade live de modelos. Os homes sintéticos devem ser privados, ter estado independente, negar autenticação inválida e impedir ferramentas irrestritas.

Se a API upstream não suportar o contrato, registrar adaptação e manter F05 bloqueada. F01 pode preparar infraestrutura independente, mas não fica declarada concluída antes de instalar/subir/testar seu próprio slice. Descobertas que mudam arquitetura viram ADR antes de implementação dependente.

## Recuperação

Experimentos usam cache fora do produto, processos/containers com identificação exclusiva e dados sintéticos. Parar somente processos criados pelo experimento. Não apagar volumes de usuário nem alterar produção. Scripts de repetição devem verificar pré-condições, preservar arquivos existentes e falhar explicitamente quando o prerequisite não estiver satisfeito.
