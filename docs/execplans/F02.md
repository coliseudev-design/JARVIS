# ExecPlan F02 — identidade e isolamento

## Slice e gate

Implementar identidade real para o piloto: convite por operador autenticado, login Argon2id, sessão opaca com cookie HttpOnly/SameSite, CSRF/Origin, revogação, recuperação por mailbox local e MFA TOTP para operações administrativas. Perfil pessoal com RLS e contexto transacional prova ownership sem antecipar chat/memória F05/F06.

A00 assume escrita de código/contratos/migrations/lockfile nesta onda, usando os documentos A01/A02/A14 já revisados; a cota dos filhos impediu continuar sua execução na onda anterior. Não há quinze implementadores concorrentes.

## Fronteiras

O componente auth é confiável para validar credenciais e resolver sujeito; sua role lê somente tabelas de identidade. Acesso a perfil usa outra conexão/role e `SET LOCAL` dentro de transação, validado por sessão/membership. IDs enviados pelo cliente não viram owner. FKs compostas preservam escopo.

TOTP administrativo obrigatório antes de administrar convites pela web. Primeiro operador é criado por comando local explícito, não por endpoint de registro público. Recuperação externa/SMTP não existe neste slice; deploy de identidade continua marcado piloto até homologação.

Caminhos ainda ausentes (SSE de chat, arquivos, jobs pessoais, integrações) são não implementados, não passes presumidos. A API não habilita esses caminhos ao habilitar autenticação. F02 não conclui F05 nem o produto completo.
